# Tasks

> Зависит от `protocol-form-catalog` (сущность формы, наследование, ось «модификация», граф).
> Идти по одной форме: сначала `pressure_common`, затем остальные.

## 1. Модель и версии

- [ ] 1.1 `ProtocolForm.structure` (JSON) + `overlay` (JSON, переопределения производной) + `renderer = "data"`.
- [ ] 1.2 Таблица `protocol_form_versions` (иммутабельные снапшоты: `structure_resolved`, `overlay`, автор, дата, комментарий).
- [ ] 1.3 Alembic-миграция; валидация структуры по `schema` на backend.
- [ ] 1.4 Резолвер структуры: цепочка родитель → потомок, наложение оверлеев; тесты на распространение и на переопределение.

## 2. Сравнение

- [ ] 2.1 Diff двух структур (по разделам/таблицам/колонкам/точкам) → список различий.
- [ ] 2.2 Разметка «наследуется / переопределено» по ключам оверлея.
- [ ] 2.3 Тесты: сравнение базы и производной; сравнение двух версий.

## 3. Рендер и генерация

- [ ] 3.1 `render_structure_html(structure, values, context)` на тех же классах/токенах.
- [ ] 3.2 Golden-тест паритета для `pressure_common` (структура vs текущий HTML), затем переключение `renderer = "data"`.
- [ ] 3.3 `GenInput.table_shape` из структуры; генератор заполняет значения по точкам; фоллбэк на прежнее поведение.
- [ ] 3.4 Тест: добавленная в структуру точка появляется в готовом протоколе.

## 4. API

- [ ] 4.1 `PUT /api/v1/templates/{code}/draft` — сохранить черновик (структура/оверлей).
- [ ] 4.2 `POST /api/v1/templates/{code}/publish` — опубликовать версию (комментарий).
- [ ] 4.3 `GET /api/v1/templates/{code}/versions` и `POST .../versions/{revision}/restore`.
- [ ] 4.4 `POST /api/v1/templates/{code}/preview` — рендер черновика по рег. номеру + модификации.
- [ ] 4.5 Проверка прав (`DEVELOPER`/`ADMINISTRATOR`) на всех изменяющих ручках; тесты 403.

## 5. Frontend: редактор

- [ ] 5.1 Редактор таблиц: добавить/удалить/переместить точку и колонку, правка заголовков и разделов.
- [ ] 5.2 Индикация «наследуется / переопределено» + кнопка «сбросить переопределение».
- [ ] 5.3 Экран сравнения: база ↔ производная и версия ↔ версия (двухпанельный diff).
- [ ] 5.4 Предпросмотр черновика на реальной строке (рег. номер + модификация) с пометкой «черновик».
- [ ] 5.5 Публикация с комментарием; история версий и откат.
- [ ] 5.6 Для не-администраторов — режим чтения без кнопок правки.

## 6. Проверка

- [ ] 6.1 `npx tsc --noEmit`, `npm run check:ui`, `npm run build`, `npm run lint` — зелёные.
- [ ] 6.2 Backend: `pytest` (резолвер оверлеев, diff, паритет рендера, права) на сервере.
- [ ] 6.3 На stage: добавить точку замера манометру для конкретной модификации, опубликовать, сгенерировать протокол и увидеть новую точку; проверить, что производные без переопределения подхватили правку базы.
