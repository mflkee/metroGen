# Tasks

> Зависит от `protocol-form-catalog` (сущность формы, наследование, ось «модификация», граф).
> Идти по одной форме: сначала `pressure_common`, затем остальные.
>
> **Статус:** механизм редактора готов (структура, оверлей-наследование, версии, права, редактор
> таблиц, предпросмотр, публикация/откат). **Отложено:** рендер протокола из структуры и переход
> формы на `renderer = "data"` (пункты 3.x — паритет с HTML-шаблоном) и экран сравнения двух форм
> (5.3); API сравнения (`diff_structures`) уже есть.

## 1. Модель и версии

- [x] 1.1 `ProtocolForm.structure` + `overlay` (JSON) — оверлей хранит только переопределения производной.
- [x] 1.2 Таблица `protocol_form_versions` (иммутабельные снапшоты: `structure_resolved`, `overlay`, автор, дата, комментарий).
- [x] 1.3 Alembic-миграция `20261015_000011_protocol_form_versions`; `validate_structure` (схема, дубли id, колонки, типы блоков).
- [x] 1.4 `resolve_structure` — цепочка родитель → потомок с наложением оверлеев; тесты на распространение правки базы и на переопределение.

## 4. API

- [x] 4.1 `PUT /api/v1/templates/{code}/draft` — черновик (структура и/или оверлей) с валидацией.
- [x] 4.2 `POST /api/v1/templates/{code}/publish` — публикация версии (комментарий, автор, время).
- [x] 4.3 `GET /api/v1/templates/{code}/versions` и `POST .../versions/{revision}/restore` (откат публикует новую версию, история не переписывается).
- [x] 4.4 `POST /api/v1/templates/{code}/preview` — предпросмотр черновика.
- [x] 4.5 Права: изменяющие ручки требуют `DEVELOPER`/`ADMINISTRATOR` (`AdminUser`); тест — `401` без токена.
