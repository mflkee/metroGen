# Design

## Context

См. `proposal.md` — Why. Текущий `FormGraph.tsx`: SVG, `d3-force` прогоняется синхронно (320 тиков) до
первого рендера, зум — `scale` внутри `transform` рядом с паном в пикселях, перетаскивания узлов нет,
подсветка соседей отсутствует, курсор читается из `ref` в разметке (то есть не обновляется).

## Goals / Non-Goals

**Goals:**

- Живой граф: узлы тянутся руками, зум/пан предсказуемы, наведение подсвечивает соседей.
- Не ломать прокрутку страницы.
- Сохранить контракт пропсов — страница не переписывается.

**Non-Goals:**

- 3D/WebGL и «мозговые» раскладки — данных десятки узлов, хватает 2D Canvas.
- Web Worker для физики — при таком размере графа не нужен.
- Настройки графа (силы, цвета) в UI — пока нет.

## Decisions

### D1: `force-graph` (Canvas) вместо самодельного SVG

`force-graph` — тонкая обёртка над `d3-force` и Canvas: перетаскивание узлов, зум вокруг курсора, пан,
наведение, клик — из коробки. Это ровно те вещи, которые я пытался написать руками и сделал плохо.

*Альтернативы:* `react-force-graph-2d` (то же + React-обвязка, но лишний слой и ещё зависимость);
`cytoscape` (мощнее, но свой стиль и вес); `Gravity UI Graph` (интересный гибрид Canvas/HTML, но это
Яндекс-экосистема и тяжелее); `Juggl` (плагин Obsidian — только как референс UX, встраивать нечего);
свой SVG + починка — отклонено: класс ошибок (координаты, хит-тесты, подписи) останется.

### D2: Тема — из CSS-переменных в рантайме

Canvas не понимает Tailwind-классы, поэтому цвета читаются через `getComputedStyle(document.documentElement)`
(`--accent`, `--text-muted`, `--tone-parent-bg`, …) и передаются в колбэки `nodeCanvasObject`,
`linkColor`. При смене темы граф перерисовывается (слушаем `data-theme` через `MutationObserver`).

### D3: Контракт пропсов не меняется

`FormGraph` по-прежнему принимает `nodes`, `links`, `query`, `selectedId`, `onSelect`, `height`.
Страница ничего не знает о библиотеке.

### D4: Поиск и фильтры — прежние

Фильтры применяются в странице (какие узлы и рёбра вообще попадают в граф), поиск — внутри компонента
(подсветка совпадений и «подтягивание» камеры). Условия (правила) остаются узлами-квадратами, формы —
кругами; HTML-форма — пунктирная обводка.

## Risks / Trade-offs

- [Зависимость ~100 КБ] → взамен уходит `d3-force` и самодельная логика; для внутреннего инструмента
  приемлемо.
- [Canvas не стилизуется классами] → D2, цвета из токенов темы, поэтому гард `fleet-ui` не ругается
  (в коде нет хардкода цветов).
- [Автоматически проверить интерактивность нельзя] → проверка ручная на stage; в тестах остаётся сборка
  и типы.

## Open Questions

- Нужна ли мини-карта и «залипание» узлов (pin) как в Obsidian? Пока нет.
- Подписывать ли рёбра (какое правило связывает условие и форму)? Пока подпись — только у узлов.
