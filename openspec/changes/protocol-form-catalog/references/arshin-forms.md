# Аршин: описание типа, методика, модификация — и как они влияют на форму протокола

Справочник для будущих задач по формам протоколов. Собран из живого Аршина (eapi + карточка типа)
и сверен с тем, как metroGen выбирает форму сейчас.

## 1. Три сущности и где они лежат

| Сущность | Что это | Поля Аршина | Где в metroGen |
|---|---|---|---|
| **Описание типа (тип СИ)** | Утверждённый тип средства измерений: «Уровнемеры многофазные», рег. номер `86065-22` | `mit_number` (рег. номер типа), `mit_title` / `mitypeTitle` (наименование), `mit_notation` / `mitypeType` (обозначение, напр. `Insol-90X`), `mitypeURL` | `excel_row["Обозначение СИ"]`, Arshin `singleMI.mitypeNumber/mitypeTitle/mitypeType` → `resolve_template_id(..., mitype_number, mitype_title)` |
| **Методика поверки** | Документ, по которому поверяют; задаёт состав операций и часто — состав таблицы | `vriInfo.docTitle` (напр. `МП 1657-7-2024`), карточка типа: раздел «Методики поверки» (`/eapi/doc/{uuid}`) | `excel_row["Методика поверки"]` или `vri.docTitle` → `method_code` |
| **Модификация** | Конкретное исполнение внутри типа: `Insol-901.1`, `902.1/3100`, `Levelflex FMP51`, `FMP54` | `singleMI.modification` (в поверке), `mi_modification` (в списке) | `excel_row["Модификация"]` / Arshin `singleMI.modification`; сейчас **в выборе формы почти не участвует** (только номер типа внутри генератора уровнемеров) |

Важно: **один номер типа содержит много модификаций**, и это норма. Пример из Аршина:

```
86065-22 «Уровнемеры многофазные» (Insol-90X) — 93 поверки, 10 вариантов написания модификации:
   Insol-90X (50), INSOL 901.1 (16), Insol-901.1 (11), 901.1 (7), 901.1/3100 (4),
   902.1/3150, 902.1/3100, 901.2, Insol-90X 901.1, INSOL-901.1.3150
47249-16 «Уровнемеры микроимпульсные» (Levelflex FMP5*) — 772 поверки, среди модификаций:
   FMP51, Levelflex FMP51, FMP54, «мод. FMP54», «исп. FMP54», Levelflex FMP57, Levelflex FMP52,
   FMP51-BAACCAUAE1AHJ+AAJA, «мод. FMP51», «Нет модификации»
```

Написание модификации в реестре **не нормализовано** («мод. FMP54», «исп. FMP54», «FMP54» — одно и
то же), поэтому сопоставлять её надо с нормализацией и по префиксу/вхождению, а не строгим равенством.

## 2. Почему форма может отличаться — три оси

### Ось 1. Методика поверки
Разные методики — разные операции и разный состав таблицы. Пример: для `86065-22` методика
`МП 1657-7-2024`; для `47249-16` — `МП 47249-16`.

Тонкость: **одна и та же методика приходит в разных редакциях/написаниях**:

```
47249-16, разные записи поверки:
   mod='Levelflex FMP51'  → docTitle='Методика поверки МП 47249-16 «Уровнемеры микроимпульсные Levelflex FMP5*» от 24.04.2018г. (с изм.№1)'
   mod='FMP54'            → docTitle='МП 47249-16'
   mod='Levelflex FMP57'  → docTitle='МП 47249-16 с изм.№1'      (и vriType=1, а не 2)
```

Вывод: код методики надо извлекать ядром (`\d{3,5}-\d{2}`), а редакцию (`с изм.№1`) — не терять,
если она меняет форму.

### Ось 2. Описание типа (рег. номер / наименование / обозначение)
Даже внутри одного вида прибора («уровнемеры») типы дают разные формы: `86065-22` (двухфазный
уровнемер с таблицей «уровень жидкости / уровень раздела») и `47249-16` (микроимпульсный с токовым
выходом) — принципиально разные таблицы.

### Ось 3. Модификация
Модификация меняет **параметры поверки, а значит и форму таблицы**. Прямое подтверждение из карточки
типа `86065-22` — межповерочный интервал и условие зависят от исполнения:

```
Условие                                                                  МПИ      Действует
для уровнемеров, работающих при избыточном давлении                       3 года   с 01.01.2022
для уровнемеров с пред допуск абс погрешн изм уровня жидких сред
  (уровня раздела сред) свыше ±3 мм                                       3 года   с 01.01.2022
для уровнемеров с пред допус абсолютной погрешности измерений уровня
  жидких сред (уровня раздела сред) ≤ ±3 мм                               1 год    с 01.01.2022
```

То есть в одном типе есть варианты с **двумя таблицами** (уровень жидкости + уровень раздела) и с
одной; наш генератор `level_meter` уже это учитывает, но **по номеру типа**, а не по модификации:

```python
# app/services/generators/level_meter.py
if template_id in ("", "level_meter"):
    wants_two_tables = mitype_number == "86065-22"
    wants_current_output = mitype_number == "47249-16"
```

`86065-22` в Аршине имеет и `901.1`, и `902.1/3150` — то есть «две таблицы» должны включаться по
модификации, а `47249-16` содержит `FMP51/52/54/57`, где токовый выход относится не ко всем.

## 3. Как повторить исследование

```bash
# список поверок типа (модификации видны сразу)
curl -sS "https://fgis.gost.ru/fundmetrology/eapi/vri?mit_number=86065-22&rows=50" | jq '.result.count, .result.items[0]'
# детали одной поверки: модификация + методика
curl -sS "https://fgis.gost.ru/fundmetrology/eapi/vri/1-524283319" | jq '.result.miInfo.singleMI, .result.vriInfo.docTitle'
# описание типа: МПИ по условиям, ссылки на методики/описания типа
curl -sS "https://fgis.gost.ru/fundmetrology/eapi/mit/65b14457-c88c-9be1-8e37-cac922ae3935" | jq '.mpi, .meth'
# карточка типа в браузере (zen): https://fgis.gost.ru/fundmetrology/cm/mits/65b14457-c88c-9be1-8e37-cac922ae3935
```

Ограничение eapi: `rows` ≤ 100 за запрос (иначе 400), дальше — `start`.

В metroGen те же данные доступны через backend: `GET /api/v1/resolve/vri-id?cert=…`,
`GET /api/v1/resolve/vri/{id}`, `POST /api/v1/resolve/vri-details-by-excel`.

## 4. Что из этого следует для metroGen

1. В правилах привязки формы (таблица `template_binding_rules`) сейчас есть поля `mitype_number`,
   `title_keyword`, `methodology_code`. **Не хватает оси «модификация»** — её надо добавить
   (`match_field = "modification"`), с нормализованным сравнением (регистр, «мод./исп.», пробелы) и
   поддержкой «начинается с» / «содержит».
2. Номер типа — слишком грубый ключ: `86065-22` покрывает и однотабличные, и двухтабличные
   исполнения. Под-форма уровнемера должна выбираться правилом по модификации, а номер типа —
   оставаться фоллбэком.
3. Методику надо хранить и показывать в её «каноническом» виде (ядро кода) + редакцию отдельно,
   чтобы правило могло отличать `МП 47249-16` от `МП 47249-16 с изм.№1`.
4. Для UI это три фильтра/оси, по которым пользователь ищет форму: **методика → тип → модификация**.
