# Proposal

## Why

Раздел «Формы протоколов» невозможно использовать: он показывает плоский список правил вида
`#28 · title_keyword «ДАВЛЕН,ДАТЧИК» → Датчики давления с токовым выходом 4–20 мА` и не отвечает ни
на один рабочий вопрос:

- какие формы вообще есть и по какому типу прибора;
- какая форма **базовая**, а какие — производные от неё (наследование);
- почему конкретная строка поверки получила именно эту форму;
- что изменится, если поправить базовую форму;
- какие формы ещё HTML-шаблоны (их нельзя редактировать), а какие — данные.

Пока этого не видно, ни редактор, ни конструктор форм обсуждать не имеет смысла. Это первый шаг:
**сделать картину видимой**.

## What Changes

- **Каталог форм по типу прибора.** Вход «Уровнемеры» → все формы этого вида: базовая (одна таблица),
  производные (две таблицы, токовый выход), с пометкой «база» / «наследует от …».
- **Граф зависимостей (как в Obsidian).** Узлы — формы и типы приборов; рёбра — наследование
  (родитель → производная) и привязки (методика / тип / модификация → форма). Поиск и фильтры:
  по типу прибора, по оси (методика / тип / модификация), по статусу (вкл/выкл), по происхождению
  (данные / HTML).
- **Инспектор «почему эта форма».** Ввод рег. номера типа, названия, методики или модификации →
  решение по шагам (override → правило → форма методики → эвристика) с подсветкой пути на графе.
- **Обратный поиск.** «Какие типы/модификации/методики попадают в эту форму» — из активных правил и
  из реестра.
- **Ось «модификация».** В правилах появляется `match_field = "modification"` (нормализованное
  сравнение: регистр, «мод./исп.», пробелы, вхождение) — это третья ось, которой сейчас нет
  (см. `references/arshin-forms.md`).
- **Пометка «HTML-only».** Формы, которые ещё рендерятся HTML-шаблоном из `app/templates/*`, помечены
  как нередактируемые — чтобы не было иллюзии, что их можно менять из UI.

## Capabilities

### New Capabilities

- `protocol-form-catalog`: как формы протоколов представлены в UI — каталог по типам приборов,
  дерево наследования, граф зависимостей с поиском и фильтрами, инспектор решения по трём осям
  (методика / описание типа / модификация) и обратный поиск.

### Modified Capabilities

- None (главных спеков в проекте пока нет).

## Impact

- **Backend**: `app/api/routes/templates.py` — расширить: дерево форм (родитель/дети), обратный
  поиск, `match_field = "modification"` в `MATCH_FIELDS` + нормализация в `template_rules`;
  каталог отдаёт признак «HTML-only» (по `TEMPLATES[...]["path"]`) и группировку по типу прибора.
- **Модель**: `template_binding_rules.match_field` получает новое значение `modification`
  (значения не enum'ом, так что миграция не нужна; нужна валидация).
- **Frontend**: страница «Формы протоколов» переписывается: каталог + граф + инспектор.
  Граф — новая зависимость (например `d3-force`/`cytoscape`) или собственная раскладка; решение в
  design.
- **Связь с другими change**: опирается на `protocol-form-mapping` (каталог `TEMPLATES`, правила,
  `resolve_form`). Готовит модель к `protocol-form-editor` (форма как сущность с родителем).
