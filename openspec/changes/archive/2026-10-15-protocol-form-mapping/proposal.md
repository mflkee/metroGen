# Proposal

## Why

Форма протокола сейчас выбирается жёстко зашитыми эвристиками: `resolve_template_id`
(`app/services/templates.py:203-233`) сопоставляет строку методики / номер типа (`mitypeNumber`) /
ключевые слова названия с одним из шести шаблонов, а `app/services/html_renderer.py:89-108`
**заново** вычисляет форму из других полей контекста и игнорирует уже вычисленный
`context["template_id"]`. Для уровнемеров разные описания типов дают разные формы, но это спрятано
в под-ветках генератора по номеру типа (`app/services/generators/level_meter.py:82-123`:
`86065-22` → две таблицы, `47249-16` → таблица токового выхода). Ни увидеть, ни изменить это из UI
нельзя: таблица `templates` в БД не засеяна и не используется, у `Methodology` нет `template_id`.
Хочется видеть и контролировать соответствие «описание типа / рег. номер → форма протокола».

## What Changes

- Ввести хранимый в БД набор **правил привязки формы** (`TemplateBindingRule`): тип прибора,
  условие (`mitype_number` | ключевое слово названия | код методики), значение, шаблон, приоритет,
  признак «включено». Правила управляются через API и UI.
- Добавить методике **форму по умолчанию** (`Methodology.template_id`).
- Разрешение формы сделать **данными вперёд**: правило по приоритету → форма методики → встроенные
  эвристики (fallback). Текущие константы `resolve_template_id` становятся fallback-слоем.
- **Рендер уважает вычисленную форму:** `render_protocol_html` использует `context["template_id"]`,
  а не пересчитывает форму из `device_info`/`methodology_full`.
- Под-формы уровнемеров вынести в **явные выбираемые варианты** (отдельные `template_id` или
  `form_variant`), а не только в скрытую ветку генератора по номеру типа.
- **UI:** админ-страница «Формы протоколов» (CRUD правил + предпросмотр, во что разворачивается
  данное описание/номер), а в рабочей зоне генерации — показ того, во что разворачивается текущий
  вход, и явный override формы на запуск.

## Capabilities

### New Capabilities

- `protocol-form-mapping`: как система определяет форму протокола для строки (данные vs эвристики),
  как это отображается и управляется из UI, включая под-формы уровнемеров.

### Modified Capabilities

- None.

## Impact

- **Backend**: новая модель + Alembic-миграция (`TemplateBindingRule`, `Methodology.template_id`);
  `app/services/templates.py` (разрешение формы), новый сервис/функция разрешения;
  `app/services/protocol_builder.py` (`template_id` в контекст), `app/services/html_renderer.py`
  (уважать `template_id`), `app/services/generators/level_meter.py` (варианты) и
  `generators/registry.py`; новый роутер правил; `app/api/routes/protocols.py` (проброс override).
- **Frontend**: новая админ-страница, запись в `src/lib/nav.ts` и `src/app/router.tsx`, изменения
  `GenerationPage.tsx` и `src/api/protocols.ts`.
- **Данные**: сид-правила, повторяющие текущие эвристики, чтобы поведение на раскатке не изменилось.
- **Контракты API**: новые эндпоинты каталога шаблонов и правил; форма резолва доступна для предпросмотра.
