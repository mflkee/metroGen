# Proposal

## Why

Каталог (`protocol-form-catalog`) покажет формы и наследование, но менять их по-прежнему нельзя: чтобы
добавить точку замера в таблицу манометра для конкретной модификации, приходится править Python
(`generators/*`) и HTML-шаблон, а затем деплоить. Владельцу нужен **конструктор**: собрать таблицу,
отредактировать шаблон, увидеть, чем формы отличаются, и сделать это как в профессиональном
редакторе — с базовым принципом наследования.

Задачи, которые это решает:

- «есть таблица манометра; для конкретной модификации нужно добавить ещё одну точку замера»;
- «у разных методик свои нюансы в протоколе» (сейчас — `МП 1657-7-2024` против `МП 47249-16`);
- «у одного описания типа разные модификации → разные таблицы» (см. `references/arshin-forms.md`).

## What Changes

- **Форма — структура, а не файл.** Форма описывается данными: разделы → таблицы → колонки → строки
  (точки замера) + текстовые блоки. Хранится в БД (`ProtocolForm.structure`), редактируется в UI.
- **Наследование с переопределением.** Производная форма наследует структуру родителя и переопределяет
  нужные части (добавить точку, колонку, изменить заголовок). Правка базовой формы распространяется на
  все производные, которые эту часть не переопределили. В UI видно, **что именно** переопределено.
- **Сравнение.** Боковое сравнение двух форм (база ↔ производная) и версий одной формы: список различий
  и diff по таблицам/колонкам/точкам.
- **Черновик → публикация, история, откат.** Формы версионируются; генерация использует опубликованную
  версию; можно посмотреть, что изменилось, и откатиться.
- **Предпросмотр на реальной строке.** До публикации — собрать протокол по конкретному рег. номеру и
  модификации и увидеть результат.
- **Постепенный переход с HTML.** Формы, которые ещё рендерятся HTML-шаблоном, остаются как есть;
  редактируемыми становятся те, что переведены на структуру. Миграция — по одной форме.
- **Права.** Редактирование — только `DEVELOPER`/`ADMINISTRATOR`; остальные видят каталог.

## Capabilities

### New Capabilities

- `protocol-form-editor`: конструктор форм протокола — структура формы как данные, наследование с
  переопределением, сравнение и версии, предпросмотр и публикация.

### Modified Capabilities

- `protocol-form-catalog`: форма перестаёт быть только «карточкой для чтения» — у неё появляется
  редактируемая структура и версии (правится дельта-спека каталога при реализации).

## Impact

- **Модель**: `ProtocolForm.structure` (JSON), таблица версий `protocol_form_versions` (или `revision` в
  самой форме + снапшоты), `renderer = "data"`.
- **Рендер**: новый generic-рендерер «структура → HTML» рядом с текущим `html_renderer` (HTML-шаблоны
  остаются фоллбэком).
- **Генераторы**: генератор заполняет значения; **форму таблицы** (колонки, набор точек) задаёт
  структура формы. Первый шаг — редактируемая «форма таблицы», значения остаются в Python.
- **Frontend**: редактор таблиц (добавить/удалить/переместить точку и колонку), панель переопределений,
  экран сравнения/diff, предпросмотр, публикация.
- **Связь**: опирается на `protocol-form-catalog` (сущность формы, наследование, граф) и на
  `protocol-form-mapping` (правила и `resolve_form`).
