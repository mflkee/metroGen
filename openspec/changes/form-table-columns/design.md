# Design

## Context

См. `proposal.md` — Why. Главная таблица манометров (`pressure.html:193-230`) — три ряда заголовков с
`colspan`/`rowspan` и девять колонок; строки генератора — словарь `si_fwd`, `si_rev`, `ref_fwd`,
`ref_rev`, `err_fwd`, `err_rev`, `var_pct`, а `allowable_error`/`allowable_variation` лежат в контексте.
У уровнемеров та же картина плюс вторая таблица и токовый выход.

## Goals / Non-Goals

**Goals:**

- Колонки становятся данными: заголовок + источник значения.
- Таблица из структуры — там, где форма уже управляет протоколом.
- Путь по умолчанию (шаблон) не меняется ни на байт.

**Non-Goals:**

- Оцифровывать многорядовые шапки (группы `colspan`/`rowspan`) — generic-таблица использует один ряд
  заголовков; прежняя шапка остаётся в шаблоне как фоллбэк.
- Управлять из структуры дополнительными таблицами уровнемера (вторая таблица, токовый выход).
- Менять генераторы: они продолжают отдавать те же ключи строк.

## Decisions

### D1: Колонка — `{id, title, source}`

`source` — ключ значения. Разрешение: строка генератора → контекст → пусто. Это позволяет колонке
показывать и измерение (`si_fwd`), и константу протокола (`allowable_error`).

*Альтернатива:* сопоставлять колонки по порядку. Отклонено — перестановка колонок в редакторе ломала бы
значения молча.

### D2: Generic-таблица — отдельный include, обёртка в шаблоне

`app/templates/_structure_table.html` рисует таблицу из `structure_table` (класс `.data-table` +
`spread-bottom-large`, чтобы вёрстка не поехала). В `pressure.html` и `level_meter.html` главная
таблица обёрнута:

```jinja
{% if structure_table %}{% include "_structure_table.html" %}{% else %}…прежняя таблица…{% endif %}
```

Фоллбэк — ровно текущая разметка, поэтому поведение без структуры не меняется.

### D3: `structure_table` собирает builder

После генерации строк:

```python
context["structure_table"] = form_structures.build_structure_table(structure, rows, context)
```

`build_structure_table` отдаёт `{"columns": [{"id","title"}], "rows": [[cell, …], …]}`. Собирается
только если форма управляет протоколом (`renderer = "data"`) и в структуре есть таблица с колонками —
иначе ключа в контексте нет и работает шаблон.

### D4: Подсказки источников — статический список по типу прибора

Редактор подсказывает ключи, которые генератор этой формы умеет отдавать (манёметры: `si_fwd`,
`ref_fwd`, `err_fwd`, `var_pct`, `allowable_error`, …; уровнемеры: `si_val`, `ref_val`, `abs_err`,
`allowable_error`). Список ведётся рядом с редактором и правится вместе с генератором — выводить ключи
из живого прогона генератора в UI дороже и хрупче.

## Risks / Trade-offs

- [Generic-таблица визуально отличается от прежней шапки] → это осознанный выбор: структура даёт свою
  шапку; форма без структуры выглядит как раньше.
- [Источник опечатан] → пустая ячейка (и это видно в предпросмотре); предпросмотр показывает источники.
- [Дополнительные таблицы уровнемера остаются в шаблоне] → зафиксировано в спеке как сценарий.

## Open Questions

- Нужны ли группы колонок (`colspan`) в generic-таблице? Пока нет — один ряд заголовков.
- Хранить ли подсказки источников в БД (рядом с формой) вместо статического списка? Пока нет.
