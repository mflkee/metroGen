# Design

## Context

См. `proposal.md` — Why. Что есть сейчас: страница на 842 строки (инспектор, фильтры, граф, редактор
структуры, история версий, сравнение, каталог), `FormGraph` (329 строк) и `StructureEditor` (295 строк).

## Goals / Non-Goals

**Goals:**

- Раздел отвечает на вопрос «сколько форм, кто от кого идёт, почему выбрана эта» — за один экран.
- Никакого редактирования в интерфейсе: нечего случайно сломать и нечего объяснять.
- Кода меньше, чем было.

**Non-Goals:**

- Редактор шаблонов, формулы, произвольные таблицы (это Excel и другой продукт — владелец это и сказал).
- Возвращать граф в каком-либо виде.
- Удалять API редактирования — он остаётся как возможность.

## Decisions

### D1: Дерево вместо графа

Формы группируются по типу прибора; внутри группы базовая форма идёт первой, производные — с отступом
под ней. Это тот же факт, что показывал граф, но без физики, зума и пустых экранов. Под каждой формой —
её правила (признак, значение, приоритет) и пометка «шаблон (HTML)» / «данные».

*Альтернатива:* починить граф (убрать `onSelect` из зависимостей эффекта). Отклонено — даже рабочий
граф не отвечает на вопрос владельца лучше, чем список; а поддержка интерактивного canvas — это код,
который придётся сопровождать.

### D2: Редактирование — только через API

`PUT /templates/{code}/draft`, `POST …/publish`, `…/versions`, `…/restore`, `…/preview` остаются и
покрыты тестами. В интерфейсе кнопок нет. Спека `protocol-form-editor` переписана так, чтобы не
обещать того, чего сервис не делает.

### D3: Инспектор и объяснение остаются

Инспектор («почему эта форма») — единственная часть, которая прямо отвечает на вопрос владельца.
Объяснение («форма выбирается по методике, типу и исполнению») и термин «признак» сохраняются: это и
есть понятность.

## Risks / Trade-offs

- [Владелец хотел редактировать таблицы] → API это умеет; если понадобится, UI делается поверх готового
  API отдельным change, но уже без «конструктора шаблонов».
- [Удаляем код, который тестировали] → тесты фронтенда покрывают сборку, а не компонент; бэкенд-тесты
  (179 passed) не затрагиваются.
- [Через месяц снова захочется граф] → данные для него остаются; решение записано здесь, чтобы не
  начинать с нуля.

## Open Questions

- Нужен ли раздел вообще, если пользователи им не пользуются? Пока он отвечает на вопрос владельца;
  если через месяц им никто не воспользуется — раздел удаляется вместе с API (одним change).
