# Proposal

## Why

Списки и справочники metroGen выглядят и ведут себя по-разному, и добавление/правка сущности
неудобны. На всех админ-страницах (`AdminOwnersPage`, `AdminMethodologiesPage`, `AdminEtalonsPage`,
`AdminAuxInstrumentsPage`) и в «Базе данных» генерации форма создания/редактирования
**вставляется сверху секции** (`showForm`/`editId`) и уводит взгляд от строки, которую правят;
таблицы не раскрываются, чтобы показать детали; часть справочников вообще нельзя удалить или
отредактировать из UI. metroLog уже решил это: карточки-аккордеоны с `aria-expanded` и шевроном,
диалог (`AppDialog`/`Modal`) для создания и правки, `DeleteConfirmModal` для удаления. Переносим
этот паттерн в metroGen единообразно.

## What Changes

- **Списки**: каждая запись — раскрывающийся элемент (`aria-expanded` + шеврон) со своими деталями;
  фильтры и поиск сохраняются.
- **Создание и правка**: открываются в модальном диалоге (`Modal`/`AppDialog`) из заголовка списка
  или из строки; форма больше не «приколота» к верху страницы. Ошибки показываются внутри диалога.
- **Удаление**: только через `DeleteConfirmModal`; отказ (например, сущность используется) виден в
  этом же диалоге.
- **Полноценный CRUD справочников** (для удобного добавления новых сущностей):
  - владельцы: удаление, управление алиасами;
  - методики: удаление, управление алиасами, редактор пунктов внутри диалога;
  - эталоны: правка (PATCH) помимо upsert, удаление, список свидетельств;
  - вспомогательные СИ: правка и удаление.
  Удаление сущности, на которую ссылаются данные, отклоняется с понятной ошибкой (HTTP 409).
- **Реестр в «Базе данных»** генерации: строки раскрываются, показывая все сохранённые поля
  (источник, лист, тип прибора, даты, номер протокола, сводку payload), без изменения фильтров.

## Capabilities

### New Capabilities

- `reference-entity-management`: единые паттерны списков (раскрывающиеся элементы), диалогов
  создания/правки, подтверждаемого удаления и полнота CRUD справочников, доступная из UI.

### Modified Capabilities

- None (главных спеков в проекте ещё нет — это первый change, который их создаёт).

## Impact

- **Frontend**: `src/pages/AdminOwnersPage.tsx`, `AdminMethodologiesPage.tsx`,
  `AdminEtalonsPage.tsx`, `AdminAuxInstrumentsPage.tsx`, `GenerationPage.tsx` (зона «База данных»);
  общий слой диалогов уже есть (`components/Modal.tsx`, `components/ui/app-dialog.tsx`,
  `components/DeleteConfirmModal.tsx`) — переиспользуется, а не переписывается.
- **Backend**: `app/api/routes/owners.py`, `methodologies.py`, `etalons.py`,
  `auxiliary_instruments.py` — добавить недостающие DELETE/PATCH и управление алиасами/свидетельствами;
  схемы (`app/schemas/*`) и сервисы (`app/services/mappings.py`) — по необходимости. Схема БД не
  меняется (новых таблиц/колонок нет).
- **Контракты**: новые ответы (409 на удаление используемой сущности) фиксируются в спеке.
